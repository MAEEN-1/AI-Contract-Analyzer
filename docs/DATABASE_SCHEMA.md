# AI Contract Analyzer — Database Schema

## Scope and implementation status

This document covers the PostgreSQL/Supabase layer of the AI Contract Analyzer. It does not describe frontend code, FastAPI logic, OpenAI calls, LangChain, RAG, PDF extraction, chunking, or embedding generation.

All migrations are applied to the Supabase project **MAEEN** (`qtgxldycxaghkvgsxbet`) and verified there:

## Authentication and security boundary

Supabase Auth is the source of truth for user identity. Application tables reference `auth.users(id)`, and read policies use `auth.uid()` to isolate users. The General Backend validates the Supabase JWT. The `SUPABASE_SERVICE_ROLE_KEY` is intended only for trusted server-side General/AI Backend processes; it bypasses RLS and must never be exposed to browser code or committed to Git.

Authenticated browser clients have owner-only `SELECT` access and no direct `INSERT`, `UPDATE`, or `DELETE` policies. Backends perform writes with trusted server credentials. The frontend therefore continues to communicate with the General Backend rather than PostgreSQL, Storage, or the AI Backend directly.

## Relationships

```text
auth.users
    |
    v
contracts
   ├── analysis_results
   ├── document_chunks
   └── chat_history
```

`chat_history` uses a composite foreign key `(contract_id, user_id) -> contracts(id, user_id)`. This prevents a row from associating a user with another user's contract at the database level, not merely through an application check. All dependent contract relationships use `ON DELETE CASCADE`.

## Tables

### `contracts`

Stores metadata for an uploaded PDF. Ownership: **General Backend**.

| Column | Type | Nullability | Default | Key / relationship |
|---|---|---:|---|---|
| `id` | `uuid` | NOT NULL | `gen_random_uuid()` | Primary key; part of composite unique key |
| `user_id` | `uuid` | NOT NULL | — | FK to `auth.users(id)`; `ON DELETE CASCADE` |
| `file_name` | `text` | NOT NULL | — | — |
| `storage_path` | `text` | NOT NULL | — | Private Storage object path |
| `status` | `text` | NOT NULL | `'uploaded'` | Check: `uploaded`, `processing`, `completed`, `failed` |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — |
| `updated_at` | `timestamptz` | NOT NULL | `now()` | Maintained by trigger |

Storage convention: `{user_id}/{contract_id}/{file_name}`. The General Backend must write exactly this object path to both Storage and `contracts.storage_path`.

### `analysis_results`

Stores structured analysis JSON returned by the AI Backend and persisted by the General Backend. Ownership: **General Backend**. `analysis` is intentionally unconstrained JSONB so the API can evolve without a database migration.

| Column | Type | Nullability | Default | Key / relationship |
|---|---|---:|---|---|
| `id` | `uuid` | NOT NULL | `gen_random_uuid()` | Primary key |
| `contract_id` | `uuid` | NOT NULL | — | FK to `contracts(id)`; `ON DELETE CASCADE` |
| `analysis` | `jsonb` | NOT NULL | — | Analysis payload |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — |
| `updated_at` | `timestamptz` | NOT NULL | `now()` | Maintained by trigger |

### `document_chunks`

Stores extracted text chunks and embeddings generated by the AI Backend. Ownership: **AI Backend**. The database does not extract, split, or embed PDFs.

| Column | Type | Nullability | Default | Key / relationship |
|---|---|---:|---|---|
| `id` | `uuid` | NOT NULL | `gen_random_uuid()` | Primary key |
| `contract_id` | `uuid` | NOT NULL | — | FK to `contracts(id)`; `ON DELETE CASCADE` |
| `chunk_text` | `text` | NOT NULL | — | — |
| `page_number` | `integer` | NULL | — | If present, must be greater than 0 |
| `embedding` | `extensions.vector(1536)` | NULL | — | Nullable until generated |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — |

### `chat_history`

Stores user questions, AI answers, and source JSON. Ownership: **General Backend**.

| Column | Type | Nullability | Default | Key / relationship |
|---|---|---:|---|---|
| `id` | `uuid` | NOT NULL | `gen_random_uuid()` | Primary key |
| `contract_id` | `uuid` | NOT NULL | — | Composite FK with `user_id`; `ON DELETE CASCADE` |
| `user_id` | `uuid` | NOT NULL | — | FK to `auth.users(id)`; also enforces contract ownership |
| `question` | `text` | NOT NULL | — | — |
| `answer` | `text` | NOT NULL | — | — |
| `sources` | `jsonb` | NOT NULL | `'[]'` | Expected source list, e.g. `[{"page":5,"text":"..."}]` |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — |

## RLS policies

RLS is enabled on all four application tables. Authenticated users can select only their own rows: contracts by `contracts.user_id`, analyses and chunks through the owning contract, and chat records by `chat_history.user_id`. No authenticated write policies exist. Anonymous users have no access. The service role is the backend-only write path and bypasses RLS.

Storage bucket `contract-pdfs` is private and has no authenticated object policies; trusted backend service-role operations are required. Uploads are capped at 50 MB per file (`file_size_limit = 52428800`). Source PDFs are not deleted by the database after processing.

## Table privileges

RLS decides which rows a role sees; table privileges decide whether the role can touch the table at all. Supabase grants `anon` and `authenticated` every privilege by default, including `TRUNCATE`, which RLS does not cover. Migration `002` narrows this:

| Role | Privileges on the four application tables |
|---|---|
| `anon` | none |
| `authenticated` | `SELECT` only, still filtered by RLS |
| `service_role` | all (backend-only, bypasses RLS) |

A new table created later does **not** inherit this. Enable RLS on it and apply the same revoke/grant pattern in its migration.

## pgvector configuration

The migration enables `vector` in the `extensions` schema and declares `embedding` as `extensions.vector(1536)`. It uses cosine distance (`<=>`) and an HNSW index with `m = 16` and `ef_construction = 64`, using `extensions.vector_cosine_ops`.

**Compatibility assumption:** the available repositories contain no AI Backend, embedding model name, or existing vector schema. Therefore the migration uses **1536 dimensions**, compatible with the commonly used OpenAI `text-embedding-3-small` model, as a provisional assumption. Before production deployment, the AI Backend owner must confirm both the exact model and output dimension. If they differ, change the vector dimension and HNSW index in a new migration before inserting embeddings; a vector dimension mismatch will reject writes.

## Indexes

| Index | Purpose |
|---|---|
| `contracts_user_id_idx` | List contracts for a user |
| `contracts_user_status_idx` | Filter a user's contracts by processing status |
| `analysis_results_contract_id_idx` | Retrieve analyses for a contract |
| `document_chunks_contract_id_idx` | Retrieve chunks for a contract |
| `chat_history_contract_created_at_idx` | Return chat history chronologically per contract |
| `chat_history_user_id_idx` | Filter chat history by owner |
| `chat_history_contract_user_idx` | Cover the composite contract/user ownership foreign key |
| `document_chunks_embedding_hnsw_idx` | Approximate cosine nearest-neighbor retrieval for non-null embeddings |

## Timestamp behavior

`public.set_updated_at()` is applied to `contracts` and `analysis_results`. Any update automatically sets `updated_at = now()`; application code does not need to maintain it.

## Backend ownership

```text
General Backend
    contracts
    analysis_results
    chat_history

AI Backend
    document_chunks
    embeddings
```

The AI flow reads `contracts.storage_path`, retrieves the private PDF, stores chunks/embeddings, and returns analysis/chat data to the General Backend. The database stores and protects data but owns none of that application logic.
