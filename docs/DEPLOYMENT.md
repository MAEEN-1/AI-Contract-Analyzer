# تشغيل منصة معين على سيرفر خاص

يشرح هذا الدليل تشغيل المنصة على سيرفر خاص (VPS) لا يشاركك فيه أحد، بعنوان ثابت وHTTPS، بدل تشغيلها من الجهاز الشخصي عبر نفق مؤقت. والملفات المستخدمة في مجلد [`deploy/`](../deploy).

## الصورة العامة

```text
التطبيق / المتصفح
      |  HTTPS فقط (شهادة تلقائية)
      v
Caddy على المنفذ 443  ──>  ملفات الواجهة (frontend/)
      |
      |  /api/* فقط
      v
الباك اند على 127.0.0.1:8000  (لا يصل إليه أحد من خارج السيرفر)
      |
      +──> Supabase (الحسابات، قاعدة البيانات، ملفات العقود في مخزن خاص)
      +──> OpenAI (التحليل والإجابات، بعد موافقة المستخدم)
```

- ملفات العقود لا تُحفظ على السيرفر؛ تبقى في مخزن Supabase الخاص كما هي الآن.
- الواجهة والـAPI على العنوان نفسه، فلا يحتاج الموقع إلى إعداد CORS.

## ما يحميه هذا الإعداد

| الحماية | كيف |
| --- | --- |
| تشفير الاتصال | Caddy يصدر شهادة HTTPS ويجددها تلقائيًا، ويحوّل أي `http://` إلى `https://`، ويرسل `Strict-Transport-Security` |
| باب واحد للسيرفر | جدار الحماية (ufw) يفتح المنافذ 22 و80 و443 فقط. والباك اند يستمع على `127.0.0.1` فقط، وCaddy يمرر له `/api/*` وحدها |
| إخفاء تفاصيل الـAPI | مع `MAEEN_ENV=production` تُغلق صفحات `/docs` و`/redoc` و`/openapi.json` |
| حماية الأسرار | ملف `backend/.env` يقرؤه root والباك اند فقط (صلاحية 640)، ولا يُرفع إلى GitHub أبدًا |
| تقييد الباك اند | يعمل بمستخدم `maeen` بلا تسجيل دخول، ولا يستطيع تعديل أي ملف على السيرفر (إعدادات systemd في `maeen-backend.service`) |
| الدخول إلى السيرفر | بمفتاح SSH فقط بعد تثبيته، وfail2ban يحظر من يكرر تخمين كلمات المرور |
| التحديثات الأمنية | تُثبَّت تلقائيًا كل يوم (unattended-upgrades) |
| ترويسات المتصفح | `Content-Security-Policy` يسمح بملفات الموقع فقط، مع منع تضمين الموقع في إطار (`X-Frame-Options`) وعدم إرسال مصدر الإحالة |

## ما تحتاجه قبل البدء

1. **سيرفر VPS** بنظام Ubuntu 24.04، وذاكرة 2 GB على الأقل (حزم تحليل PDF تحتاجها). أي شركة تقدم VPS مناسبة.
2. **دومين** تملكه، مثل `maeen-app.com`.
3. **مفتاح SSH** على جهازك (الخطوة 1).

### اختيار المنطقة

بيانات المستخدمين في السعودية يشملها نظام حماية البيانات الشخصية. إذا كان مطلوبًا أن تبقى البيانات داخل المملكة، فاختر سيرفرًا في منطقة سعودية (مثل Oracle Cloud في جدة أو الرياض، أو Google Cloud في الدمام). وانتبه إلى أن ملفات العقود نفسها في Supabase (طوكيو حاليًا) وأن النص يُرسل إلى OpenAI، فنقل السيرفر وحده لا يُبقي كل البيانات داخل المملكة. يُنصح بالتحقق من المطلوب مع المشرف على المشروع.

## الخطوات

### 1. إنشاء مفتاح SSH على جهازك

في PowerShell على جهازك:

```bash
ssh-keygen -t ed25519 -C "maeen-server"
```

اضغط Enter للمسار الافتراضي، واكتب عبارة مرور. ثم اعرض المفتاح العام لنسخه:

```bash
type $env:USERPROFILE\.ssh\id_ed25519.pub
```

### 2. إنشاء السيرفر

في لوحة الشركة: Ubuntu 24.04، وذاكرة 2 GB أو أكثر، والصق المفتاح العام في خانة SSH key. احفظ عنوان IP الذي يظهر لك.

### 3. ربط الدومين بالسيرفر

في إعدادات الدومين (DNS) أضف سجلًا من نوع `A`: الاسم `@` (أو اسم فرعي مثل `app`) والقيمة عنوان IP للسيرفر. قد يستغرق ظهوره دقائق إلى ساعات.

### 4. تجهيز السيرفر

ادخل إلى السيرفر:

```bash
ssh root@SERVER_IP
```

ثم نزّل سكربت التجهيز وشغّله مع الدومين:

```bash
curl -fsSLO https://raw.githubusercontent.com/MAEEN-1/AI-Contract-Analyzer/main/deploy/setup.sh
```

```bash
bash setup.sh maeen-app.com
```

يثبّت السكربت التحديثات وCaddy وجدار الحماية، وينزّل المشروع في `/srv/maeen/app`، ويجهّز الخدمات، ويوقف الدخول بكلمة مرور ما دام مفتاحك مثبتًا. ولا يشغّل الباك اند قبل تعبئة الأسرار.

### 5. تعبئة الأسرار

```bash
nano /srv/maeen/app/backend/.env
```

| الإعداد | القيمة |
| --- | --- |
| `MAEEN_ENV` | `production` |
| `SUPABASE_URL` | كما في جهازك |
| `SUPABASE_KEY` | مفتاح service_role من لوحة Supabase |
| `SUPABASE_DB_URL` | رابط Session pooler من لوحة Supabase |
| `OPENAI_API_KEY`، `CHAT_MODEL`، `CHAT_REASONING_EFFORT`، `EMBEDDING_MODEL` | كما في جهازك |
| `FRONTEND_URL` | `capacitor://localhost` إذا كان تطبيق iOS مبنيًا بـCapacitor، وإلا اتركه فارغًا |

احفظ بـ Ctrl+O ثم Enter، واخرج بـ Ctrl+X. لا ترسل هذه القيم لأحد ولا تلصقها في محادثة.

### 6. التشغيل والتحقق

```bash
systemctl start maeen-backend
```

```bash
systemctl status maeen-backend
```

ثم تحقق من جهازك:

- `https://maeen-app.com` تفتح الصفحة الرئيسية بقفل HTTPS.
- `https://maeen-app.com/api/auth/me` ترد `{"detail":"Bearer token is required"}`، أي أن الباك اند يعمل.
- `https://maeen-app.com/docs` لا تعرض صفحة الـAPI.

### 7. ربط تطبيق iOS

في نسخة الواجهة داخل التطبيق، عرّف عنوان السيرفر قبل تحميل `app.js`:

```html
<script>window.MAEEN_API_URL = "https://maeen-app.com";</script>
```

بدونه يحاول التطبيق الاتصال بـ`127.0.0.1:8000` على الجوال نفسه، لأن Capacitor يفتح الصفحات من `localhost`. وأضف `capacitor://localhost` إلى `FRONTEND_URL` كما في الخطوة 5.

## بعد التشغيل

### تحديث السيرفر بعد دمج تعديلات في main

```bash
bash /srv/maeen/app/deploy/update.sh
```

### السجلات

```bash
journalctl -u maeen-backend -f
```

سجل الزيارات في `/var/log/caddy/maeen-access.log`.

### تحليل عالق

إذا أُعيد تشغيل الباك اند أثناء تحليل عقد، يبقى العقد «جارٍ التحليل». أوقف الخدمة، ثم علّم التحليل متعثرًا، ثم شغّلها؛ ويستطيع المستخدم بعدها إعادة التحليل:

```bash
systemctl stop maeen-backend
```

```bash
cd /srv/maeen/app/backend && sudo -u maeen /srv/maeen/venv/bin/python recover_stale_analysis.py USER_ID CONTRACT_ID --workers-stopped
```

```bash
systemctl start maeen-backend
```

## مسؤوليات صاحب الحسابات

- فعّل التحقق بخطوتين في حسابات شركة السيرفر وSupabase وGitHub وOpenAI.
- إذا ظهر أي مفتاح سري خارج السيرفر (في محادثة أو صورة أو commit)، غيّره فورًا من لوحة الخدمة ثم حدّث `.env` وأعد تشغيل الباك اند.
- المستودع على GitHub عام، فلا تضع فيه أي سر أو بيانات مستخدمين.
- فعّل النسخ الاحتياطي التلقائي للسيرفر إن كانت الشركة تقدمه.
