### 3. Supabase Auth assumptions

Supabase Auth is the source of truth for user identity. All user ownership checks use the authenticated Supabase UUID and `auth.uid()`.

Use these rules:

1. `contracts.user_id` references `auth.users(id)`.
2. `chat_history.user_id` references `auth.users(id)`.
3. RLS policies use `auth.uid()`.
4. The General Backend validates Supabase JWTs.
5. The Supabase service-role key is backend-only.
6. Never expose the service-role key to frontend code, browser JavaScript, public documentation, or API responses.
7. Do not create a custom users table unless a separate, explicit profile requirement is added later.

The `chat_history` table must use a composite relationship from `(contract_id, user_id)` to `(contracts.id, contracts.user_id)`. This is a database-level guarantee that a chat record cannot associate a user with another user's contract.

### 5. Complete migration SQL

Create a Supabase migration file named similar to:


Use the following SQL. It is the complete database foundation applied to MAEEN, including the final ownership index.

```sql
-- AI Contract Analyzer database foundation
-- Safe to run on a new Supabase project. No DROP/TRUNCATE operations are used.

create extension if not exists vector with schema extensions;

create table if not exists public.contracts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  file_name text not null,
  storage_path text not null,
  status text not null default 'uploaded' check (status in ('uploaded', 'processing', 'completed', 'failed')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint contracts_id_user_id_key unique (id, user_id)
);

create table if not exists public.analysis_results (
  id uuid primary key default gen_random_uuid(),
  contract_id uuid not null references public.contracts(id) on delete cascade,
  analysis jsonb not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table if not exists public.document_chunks (
  id uuid primary key default gen_random_uuid(),
  contract_id uuid not null references public.contracts(id) on delete cascade,
  chunk_text text not null,
  page_number integer check (page_number is null or page_number > 0),
  -- Confirm the final AI Backend embedding model before production rollout.
  embedding extensions.vector(1536),
  created_at timestamptz not null default now()
);

create table if not exists public.chat_history (
  id uuid primary key default gen_random_uuid(),
  contract_id uuid not null,
  user_id uuid not null references auth.users(id) on delete cascade,
  question text not null,
  answer text not null,
  sources jsonb not null default '[]'::jsonb,
  created_at timestamptz not null default now(),
  constraint chat_history_contract_user_fkey
    foreign key (contract_id, user_id)
    references public.contracts (id, user_id)
    on delete cascade
);

create index if not exists contracts_user_id_idx
  on public.contracts (user_id);

create index if not exists contracts_user_status_idx
  on public.contracts (user_id, status);

create index if not exists analysis_results_contract_id_idx
  on public.analysis_results (contract_id);

create index if not exists document_chunks_contract_id_idx
  on public.document_chunks (contract_id);

create index if not exists chat_history_contract_created_at_idx
  on public.chat_history (contract_id, created_at desc);

create index if not exists chat_history_user_id_idx
  on public.chat_history (user_id);

-- Covers the composite foreign key used to enforce chat ownership.
create index if not exists chat_history_contract_user_idx
  on public.chat_history (contract_id, user_id);

create index if not exists document_chunks_embedding_hnsw_idx
  on public.document_chunks
  using hnsw (embedding extensions.vector_cosine_ops)
  with (m = 16, ef_construction = 64)
  where embedding is not null;

create or replace function public.set_updated_at()
returns trigger
language plpgsql
security invoker
set search_path = public
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

drop trigger if exists contracts_set_updated_at on public.contracts;
create trigger contracts_set_updated_at
before update on public.contracts
for each row execute function public.set_updated_at();

drop trigger if exists analysis_results_set_updated_at on public.analysis_results;
create trigger analysis_results_set_updated_at
before update on public.analysis_results
for each row execute function public.set_updated_at();

alter table public.contracts enable row level security;
alter table public.analysis_results enable row level security;
alter table public.document_chunks enable row level security;
alter table public.chat_history enable row level security;

drop policy if exists contracts_select_own on public.contracts;
create policy contracts_select_own
on public.contracts
for select to authenticated
using (user_id = (select auth.uid()));

drop policy if exists analysis_results_select_own on public.analysis_results;
create policy analysis_results_select_own
on public.analysis_results
for select to authenticated
using (exists (
  select 1
  from public.contracts c
  where c.id = analysis_results.contract_id
    and c.user_id = (select auth.uid())
));

drop policy if exists document_chunks_select_own on public.document_chunks;
create policy document_chunks_select_own
on public.document_chunks
for select to authenticated
using (exists (
  select 1
  from public.contracts c
  where c.id = document_chunks.contract_id
    and c.user_id = (select auth.uid())
));

drop policy if exists chat_history_select_own on public.chat_history;
create policy chat_history_select_own
on public.chat_history
for select to authenticated
using (user_id = (select auth.uid()));

-- Private bucket. Backends use SUPABASE_SERVICE_ROLE_KEY for upload,
-- retrieval, and deletion.
insert into storage.buckets (
  id,
  name,
  public,
  allowed_mime_types
)
values (
  'contract-pdfs',
  'contract-pdfs',
  false,
  array['application/pdf']::text[]
)
on conflict (id) do update set
  name = excluded.name,
  public = false,
  allowed_mime_types = excluded.allowed_mime_types;

-- No authenticated Storage policies are granted intentionally.
-- Browser Storage access is denied. The service role bypasses RLS
-- for trusted General/AI Backend operations.

comment on table public.contracts is
  'PDF contract metadata; writes owned by General Backend.';

comment on table public.analysis_results is
  'AI analysis JSON returned to and persisted by General Backend.';

comment on table public.document_chunks is
  'Extracted chunks and optional embeddings; writes owned by AI Backend.';

comment on table public.chat_history is
  'Contract chat records and source JSON; writes owned by General Backend.';

comment on column public.contracts.storage_path is
  'Private contract-pdfs object path: {user_id}/{contract_id}/{file_name}.';

comment on column public.document_chunks.embedding is
  '1536-dimensional cosine-search vector; confirm model/dimension with AI Backend before production.';

-- No INSERT/UPDATE/DELETE policies are created for authenticated users.
-- This prevents direct frontend writes. Trusted server credentials bypass RLS.
```

### 6. Table contract details

#### `public.contracts`

This table stores PDF metadata. It is owned by the General Backend.

Required columns:

```text
id            uuid primary key default gen_random_uuid()
user_id       uuid not null references auth.users(id) on delete cascade
file_name     text not null
storage_path  text not null
status        text not null default 'uploaded'
created_at    timestamptz not null default now()
updated_at    timestamptz not null default now()
```

The `status` check constraint allows only:

```text
uploaded
processing
completed
failed
```

The Storage path convention is:

```text
{user_id}/{contract_id}/{file_name}
```

Example:

```text
user-uuid/contract-uuid/agreement.pdf
```

The value in `contracts.storage_path` must exactly match the object path used in the private `contract-pdfs` bucket.

#### `public.analysis_results`

This table stores analysis data returned from the AI Backend and persisted by the General Backend.

Required columns:

```text
id           uuid primary key default gen_random_uuid()
contract_id  uuid not null references contracts(id) on delete cascade
analysis     jsonb not null
created_at   timestamptz not null default now()
updated_at   timestamptz not null default now()
```

Do not add a uniqueness constraint on `contract_id` unless the application API explicitly requires exactly one analysis per contract. The current schema allows multiple analysis records per contract.

The JSONB value may contain a structure similar to:

```json
{
  "summary": "string",
  "parties": [
    {
      "name": "string",
      "role": "string"
    }
  ],
  "obligations": [
    {
      "party": "string",
      "description": "string"
    }
  ],
  "payment_terms": {
    "description": "string",
    "amount": "string",
    "due_date": "string"
  },
  "termination": {
    "description": "string",
    "notice_period": "string"
  },
  "renewal": {
    "description": "string",
    "automatic": true
  },
  "important_clauses": [
    {
      "title": "string",
      "description": "string",
      "page": 1
    }
  ],
  "risks": [
    {
      "title": "string",
      "description": "string",
      "severity": "low"
    }
  ]
}
```

The database intentionally does not validate every internal JSON field. The API contract owns the internal JSON structure.

#### `public.document_chunks`

This table stores text chunks and embeddings generated by the AI Backend. The database does not extract text, split PDFs, or generate embeddings.

Required columns:

```text
id           uuid primary key default gen_random_uuid()
contract_id  uuid not null references contracts(id) on delete cascade
chunk_text   text not null
page_number  integer nullable
embedding    extensions.vector(1536) nullable
created_at   timestamptz not null default now()
```

When `page_number` is present, it must be greater than zero. `embedding` remains nullable while a chunk is waiting for embedding generation.

The current provisional vector configuration is:

```text
Embedding model assumption: OpenAI text-embedding-3-small
Vector dimension: 1536
Distance metric: cosine distance
Index: HNSW
m: 16
ef_construction: 64
Operator class: extensions.vector_cosine_ops
```

The available application repositories did not include the AI Backend or its embedding configuration. Therefore, `vector(1536)` is a documented compatibility assumption. Before production processing begins, confirm the exact model and output dimension in the AI Backend. If the dimension differs, create a new migration that changes the vector type and index before inserting embeddings.

An example semantic retrieval query is:

```sql
select
  id,
  contract_id,
  chunk_text,
  page_number,
  1 - (embedding <=> $1) as similarity
from public.document_chunks
where contract_id = $2
  and embedding is not null
order by embedding <=> $1
limit 10;
```

#### `public.chat_history`

This table stores questions, answers, and source references. It is owned by the General Backend.

Required columns:

```text
id           uuid primary key default gen_random_uuid()
contract_id  uuid not null
user_id      uuid not null references auth.users(id) on delete cascade
question     text not null
answer       text not null
sources      jsonb not null default '[]'::jsonb
created_at   timestamptz not null default now()
```

The ownership constraint is:

```sql
foreign key (contract_id, user_id)
references public.contracts (id, user_id)
on delete cascade
```

A typical `sources` value is:

```json
[
  {
    "page": 5,
    "text": "Relevant contract text"
  }
]
```

### 7. RLS policy behavior

RLS is enabled on all four public application tables:

```text
contracts
analysis_results
document_chunks
chat_history
```

Authenticated users have owner-only read access:

- Contracts are visible only when `contracts.user_id = auth.uid()`.
- Analysis results are visible only when their contract belongs to `auth.uid()`.
- Document chunks are visible only when their contract belongs to `auth.uid()`.
- Chat history is visible only when `chat_history.user_id = auth.uid()`.

No authenticated `INSERT`, `UPDATE`, or `DELETE` policies exist. This means:

- `INSERT` is rejected with a PostgreSQL RLS error.
- `UPDATE` affects zero rows when the authenticated user has no applicable write policy.
- `DELETE` affects zero rows when the authenticated user has no applicable write policy.
- Trusted backend service-role operations bypass RLS.

Do not create broad policies such as `using (true)` or `with check (true)` for authenticated users.

### 8. Storage configuration

Create or reconcile this bucket:

```text
Bucket ID: contract-pdfs
Bucket name: contract-pdfs
Public: false
Allowed MIME type: application/pdf
```

The original PDF must remain in Storage after AI processing. The database must not delete the PDF automatically. The General Backend owns upload, deletion, and `storage_path` maintenance. The AI Backend retrieves the PDF for processing by reading the contract metadata and using trusted backend credentials.

No authenticated browser Storage policies are granted. This keeps private file operations behind the backend boundary.

### 9. Verification SQL

Create a file similar to:

```text
supabase/tests/verify_schema.sql
```

Use this schema verification SQL after applying the migration:

```sql
-- Run with a privileged connection after applying the migration.
-- These assertions fail loudly when the target schema is incompatible.

do $$
declare
  v_count bigint;
  v_def text;
begin
  select count(*) into v_count
  from information_schema.tables
  where table_schema = 'public'
    and table_name in (
      'contracts',
      'analysis_results',
      'document_chunks',
      'chat_history'
    );

  if v_count <> 4 then
    raise exception 'Expected 4 application tables, got %', v_count;
  end if;

  select pg_get_constraintdef(oid) into v_def
  from pg_constraint
  where conrelid = 'public.contracts'::regclass
    and contype = 'c'
    and conname like '%status%';

  if v_def is null
     or v_def not like '%uploaded%'
     or v_def not like '%processing%'
     or v_def not like '%completed%'
     or v_def not like '%failed%' then
    raise exception 'contracts.status check constraint is missing or incomplete';
  end if;

  if not exists (
    select 1
    from pg_attribute
    where attrelid = 'public.document_chunks'::regclass
      and attname = 'embedding'
  ) then
    raise exception 'document_chunks.embedding is missing';
  end if;

  if not exists (
    select 1
    from pg_indexes
    where schemaname = 'public'
      and indexname = 'document_chunks_embedding_hnsw_idx'
  ) then
    raise exception 'HNSW vector index is missing';
  end if;

  if not exists (
    select 1
    from pg_policies
    where schemaname = 'public'
      and tablename = 'contracts'
      and policyname = 'contracts_select_own'
  ) then
    raise exception 'contracts owner SELECT policy is missing';
  end if;

  if not exists (
    select 1
    from storage.buckets
    where id = 'contract-pdfs'
      and public = false
      and 'application/pdf' = any(allowed_mime_types)
  ) then
    raise exception 'contract-pdfs bucket is not private or does not allow application/pdf';
  end if;
end $$;

select 'schema verification passed' as result;
```

### 10. Seed Data and RLS test procedure

Use isolated temporary test data only. Never leave test users or test contracts in MAEEN.

The verified test procedure used a single transaction and finished with `ROLLBACK`. It created two temporary users, two contracts, analysis records, document chunks, and chat records. It then checked the following:

1. User A could read User A's contract.
2. User A could read User A's analysis.
3. User A could read User A's document chunks.
4. User A could read User A's chat history.
5. User A could not read User B's contract.
6. User A could not read User B's analysis.
7. User A could not read User B's document chunks.
8. User A could not read User B's chat history.
9. Authenticated direct `INSERT` was rejected with SQLSTATE `42501`.
10. Authenticated direct `UPDATE` affected zero rows.
11. Authenticated direct `DELETE` affected zero rows.
12. Deleting a contract cascaded to analysis, chunks, and chat history.
13. The transaction was rolled back.

After rollback, the following counts were verified:

```text
test_users_remaining      = 0
test_contracts_remaining  = 0
test_analysis_remaining   = 0
test_chunks_remaining     = 0
test_chats_remaining       = 0
```

The first attempted test intentionally demonstrated that an unhandled authenticated `INSERT` is rejected by RLS. The final test corrected the harness by catching the expected `42501` error and checking `ROW_COUNT = 0` for `UPDATE` and `DELETE`.

When reproducing this test, use placeholder email addresses under `.invalid`, use deterministic UUIDs that cannot collide with real data, and always run the entire test inside a transaction that ends with `ROLLBACK`.

### 13. Expected backend flows

The database must support these existing application flows without owning their business logic.

#### Contract upload

```text
General Backend receives PDF
    ↓
General Backend creates contract UUID
    ↓
General Backend uploads to private bucket contract-pdfs
    ↓
Storage path: {user_id}/{contract_id}/{file_name}
    ↓
General Backend inserts contracts row with status uploaded
```

#### AI processing

```text
AI Backend receives contract_id
    ↓
Reads contracts.storage_path with trusted backend credentials
    ↓
Retrieves original PDF from contract-pdfs
    ↓
Extracts text and creates chunks outside the database
    ↓
Generates embeddings outside the database
    ↓
Inserts document_chunks rows
    ↓
Updates contract status through trusted backend credentials
```

#### Analysis

```text
AI Backend analyzes the contract
    ↓
Returns structured analysis to General Backend
    ↓
General Backend inserts analysis_results row
```

#### Chat

```text
AI Backend receives contract_id and question
    ↓
Generates query embedding outside the database
    ↓
Uses pgvector cosine retrieval against document_chunks
    ↓
Generates answer and sources outside the database
    ↓
General Backend inserts chat_history row
```
